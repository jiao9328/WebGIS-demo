  Thought for 21s (ctrl+o to expand)

● 给组员发权限后,他们克隆 → 改代码 → 提交 → 推送,每次推送在 GitHub
  上都会留下完整痕迹(谁、什么时候、改了什么)。关键是让每个组员先配置自己的 git
  身份,否则留痕会混成一个人的。下面是给组员的标准操作,你可以直接转发到群里:

  ---

  📋 组员第一次操作(发到群里)

  # 1. 先配置身份(用自己注册 GitHub 的邮箱,留痕就靠它)
  git config --global user.name "你的姓名"
  git config --global user.email "你注册GitHub的邮箱"

  # 2. 克隆并运行
  git clone https://github.com/jiao9328/WebGIS-demo.git
  cd WebGIS-demo
  pnpm install
  pnpm dev

  ⚠️ 还需要密钥:仓库是公开的,.env 不在里面(含密钥无法上传)。向组长单独要 .env 文件,放进项目根目录,地图才能加载。

  📋 组员日常修改上传(每次都要)

  git add 你改的文件          # 只加你改的,别 git add .
  git commit -m "做了什么:如 修复导航按钮样式"
  git pull --rebase origin main   # 先同步别人的最新提交(关键一步!)
  git push origin main

  ▎ 如果 git push 被拒绝(提示 non-fast-forward),说明别人先推了——再执行一次上面两条(pull --rebase → push)即可。

  ---

  留痕体现在哪(给老师看分工的凭证):
  - 仓库 Commits 页:每条提交显示作者头像、姓名、时间、改动内容
  - Insights → Contributors:柱状图直接展示每个成员的提交数量分布,分工一目了然
  - 具体代码是谁写的:进文件点 Blame,逐行显示归属

  三个容易翻车的点,提醒组员注意:
  1. 身份没配好 → 提交会显示成别人的名字或"Unknown",留痕作废。每人务必先跑第一条 git config
  2. .env 绝不提交:已被 .gitignore 拦住,但千万别用 git add -f .env 强推;密钥泄露 GitHub 会自动拦截,泄露后所有 key
     都得作废重发
  3. dist/、node_modules 都已被忽略,不用管

  如果你想要更严格的留痕(每人一个分支 + Pull Request 审批记录),告诉我,我可以给你配分支保护规则和 PR 流程说明。

● 上面那两段命令块直接转发到你们小组群即可。

  补充提醒两点:

  1. 确认权限给到位:你邀请组员后,要确保他们的角色是 Write(不是 Read)——GitHub 仓库页面 → Settings →
     Collaborators,每个人旁应有 Write 标识,他们才能 push。Read 权限只能看不能传。
  2. 首次推送前组员必须跑 git config 那两行,不然提交会显示为机器默认名,Contributors 图上对不上人,留痕就白留了。

  等组员推几条提交后,你可以在仓库 Insights → Contributors
  看到成员分布图,用于分工记录。如果之后想要更严格的留痕(组员改分支 + 发 Pull
  Request,你审批合并,每一步都有审批记录),随时叫我帮你配置。
